# Fixos (ganhos e gastos recorrentes previstos) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Uma tela nova "Fixos" onde o usuário cadastra ganhos/gastos recorrentes e previsíveis (salário, aluguel, assinaturas); o app gera sozinho, todo mês, um lançamento previsto no mês seguinte ao mês real de hoje, que aparece nas telas normais de Ganhos/Gastos e entra nos cálculos — travado para edição/exclusão até o mês real chegar.

**Architecture:** Novo modelo `Fixo` (molde recorrente, coleção própria) + campo `origemFixoId` em `Ganho`/`Gasto` (liga o lançamento gerado ao molde) + campo `previsto` novo em `Gasto` (hoje só existe em `Ganho`). Um provider roda uma vez por sessão do app e garante que cada Fixo ativo tenha um lançamento gerado para o mês seguinte. A trava de edição é checada na UI das telas de Ganhos/Gastos, não no repositório.

**Tech Stack:** Flutter + Riverpod (mesmos padrões já usados em todo o app: `Provider`/`Provider.autoDispose`/`StreamProvider`/`FutureProvider`, `combinarAsyncValues`, repositórios abstratos com implementação Firestore + fake em memória).

**Spec:** `docs/superpowers/specs/2026-10-09-fixos-design.md`

## Global Constraints

- Mês-alvo da geração é sempre `MesRef.atual().avancar(1)` — o mês real de hoje, nunca o mês selecionado na tela (`mesSelecionadoProvider`).
- A trava de edição/exclusão vale SÓ para lançamentos com `origemFixoId` preenchido e mês ainda futuro. O checkbox "Previsto" manual existente (sem `origemFixoId`) continua sem trava, do jeito que já funciona.
- `gastosEfetivos`/`gastosEfetivosNaJanela` espelham exatamente `ganhosEfetivos`/`ganhosEfetivosNaJanela` já existentes — real sempre vence previsto, por pessoa, nunca misturando meses diferentes de uma janela.
- Excluir um `Fixo` não apaga lançamentos já gerados por ele — só para de gerar novos.
- `comprometidoNoMes`/`percentualComprometidoProvider`/`estouroProjetadoProvider` não mudam — são sobre parcelas, um conceito ortogonal a "previsto".
- Editar um `Fixo` já criado está fora de escopo (só criar e excluir).
- Geração retroativa de meses pulados está fora de escopo — cada abertura do app só garante o mês seguinte a partir de hoje.

```dart
enum TipoFixo { ganho, gasto }

/// Molde de um ganho ou gasto recorrente e previsivel (salario, aluguel,
/// assinatura): enquanto existir, gera um lancamento previsto (Ganho ou
/// Gasto, conforme [tipo]) no mes seguinte ao mes real de hoje, toda vez
/// que o app verifica (ver `garantirFixosDoMesProvider` em
/// lib/estado/providers.dart).
///
/// Excluir o Fixo so impede gerar NOVOS meses -- lancamentos que ele ja
/// gerou continuam existindo, independentes dele a partir dai.
class Fixo {
  final String id;
  final TipoFixo tipo;
  final String membroId;
  final String descricao;
  final double valor;

  /// So para `tipo == TipoFixo.gasto`. Nulo (e sem sentido) para ganho.
  final String? poteId;

  final DateTime criadoEm;

  const Fixo({
    required this.id,
    required this.tipo,
    required this.membroId,
    required this.descricao,
    required this.valor,
    required this.criadoEm,
    this.poteId,
  });

  factory Fixo.fromMap(String id, Map<String, dynamic> mapa) => Fixo(
        id: id,
        tipo: (mapa['tipo'] as String) == 'ganho'
            ? TipoFixo.ganho
            : TipoFixo.gasto,
        membroId: mapa['membroId'] as String,
        descricao: mapa['descricao'] as String,
        valor: (mapa['valor'] as num).toDouble(),
        criadoEm: _lerData(mapa['criadoEm']),
        poteId: mapa['poteId'] as String?,
      );

  Map<String, dynamic> toMap() => {
        'tipo': tipo == TipoFixo.ganho ? 'ganho' : 'gasto',
        'membroId': membroId,
        'descricao': descricao,
        'valor': valor,
        'criadoEm': criadoEm,
        'poteId': poteId,
      };
}

DateTime _lerData(dynamic bruto) {
  if (bruto is DateTime) return bruto;
  if (bruto == null) return DateTime.now();
  return (bruto as dynamic).toDate() as DateTime;
}
```

class RepositorioFixosFake implements RepositorioFixos {
  final List<Fixo> _fixos = [];
  final _controlador = StreamController<void>.broadcast();
  var _sequencia = 0;

  List<Fixo> get todos => List.unmodifiable(_fixos);

  @override
  Stream<List<Fixo>> observar() =>
      _correnteEDepois(_controlador.stream, () => List<Fixo>.unmodifiable(_fixos));

  @override
  Future<void> adicionar(Fixo fixo) async {
    _fixos.add(_comId(fixo, 'fixo-${_sequencia++}'));
    _controlador.add(null);
  }

  @override
  Future<void> remover(String id) async {
    _fixos.removeWhere((f) => f.id == id);
    _controlador.add(null);
  }
}

Fixo _comId(Fixo fixo, String id) => Fixo(
      id: id,
      tipo: fixo.tipo,
      membroId: fixo.membroId,
      descricao: fixo.descricao,
      valor: fixo.valor,
      criadoEm: fixo.criadoEm,
      poteId: fixo.poteId,

class FixosFirestore implements RepositorioFixos {
  final FirebaseFirestore db;
  final String casaId;
  FixosFirestore(this.db, this.casaId);

  CollectionReference<Map<String, dynamic>> get _col =>
      _casaDoc(db, casaId).collection('fixos');

  @override
  Stream<List<Fixo>> observar() => _col.snapshots().map(
      (s) => s.docs.map((d) => Fixo.fromMap(d.id, d.data())).toList());

  @override
  Future<void> adicionar(Fixo fixo) => _col.add(fixo.toMap());

  @override
  Future<void> remover(String id) => _col.doc(id).delete();
}
```

/// Mesma regra de `ganhosEfetivos`, para gastos: o gasto real de uma
/// pessoa vence o previsto dela no mesmo mes; nunca mistura os dois.
/// Assume que [gastosDoMes] ja pertence a um unico mes (mesmo contrato de
/// `ganhosEfetivos`) -- para uma janela com varios meses, ver
/// `gastosEfetivosNaJanela`, logo abaixo.
List<Gasto> gastosEfetivos(List<Gasto> gastosDoMes) {
  final membrosComReal = <String>{
    for (final g in gastosDoMes)
      if (!g.previsto) g.membroId,
  };
  return [
    for (final g in gastosDoMes)
      if (!g.previsto || !membrosComReal.contains(g.membroId)) g,
  ];
}
```

/// `gastosEfetivos`, mes a mes, para uma janela com varios meses
/// misturados (ex.: `gastosDoIntervaloProvider`) -- mesmo motivo de
/// `ganhosEfetivosNaJanela` existir separado de `ganhosEfetivos`: aplicar
/// a regra sobre a janela inteira de uma vez misturaria "tem gasto real
/// em setembro" com "tem previsto em novembro" da mesma pessoa, quando
/// sao perguntas independentes.
List<Gasto> gastosEfetivosNaJanela(List<Gasto> gastosDoIntervalo) {
  final porMes = <String, List<Gasto>>{};
  for (final g in gastosDoIntervalo) {
    (porMes[g.mesRef] ??= []).add(g);
  }
  return [
    for (final lista in porMes.values) ...gastosEfetivos(lista),
  ];
}

/// Mes-alvo da geracao: sempre o mes seguinte ao mes REAL de hoje (nao o
/// mes selecionado na tela).
MesRef mesAlvoDosFixos() => MesRef.atual().avancar(1);

/// Os Fixos que AINDA NAO tem um lancamento gerado para [mesAlvo]
/// (comparando o id do Fixo contra `origemFixoId` dos lancamentos ja
/// existentes naquele mes, em [origensJaGeradasNoMes]). [mesAlvo] nao
/// entra na comparacao em si -- quem monta `origensJaGeradasNoMes` ja
/// filtrou pelo mes certo antes de chamar esta funcao.
List<Fixo> fixosParaGerar({
  required List<Fixo> fixos,
  required MesRef mesAlvo,
  required Set<String> origensJaGeradasNoMes,
}) =>
    [
      for (final f in fixos)
        if (!origensJaGeradasNoMes.contains(f.id)) f,
    ];

/// Verdadeiro quando o lancamento veio de um Fixo E o mes dele ainda nao
/// chegou (mesRef depois do mes real de hoje) -- so entao fica travado
/// para edicao/exclusao. Lancamentos sem origemFixoId (previsto manual,
/// ou qualquer lancamento normal) nunca travam.
bool travadoPorFixo({required String? origemFixoId, required String mesRef}) =>
    origemFixoId != null && MesRef.parse(mesRef).compareTo(MesRef.atual()) > 0;

/// Roda uma vez por sessao do app (nao autoDispose, nao fica relendo a

/// para `mesAlvoDosFixos()` e cria o que faltar. Chamado a partir do
/// Shell, assim que a casa resolve (ver lib/ui/shell.dart).
///
/// Le os repositorios diretamente (`.observar().first`/`.observarMes(...)
/// .first`), nao atraves de `fixosProvider`/`ganhosDoMesProvider`: isto e
/// uma checagem pontual de "o que existe agora", nao algo que precisa
/// recalcular quando o stream emitir de novo.
final garantirFixosDoMesProvider = FutureProvider<void>((ref) async {
  final repoFixos = ref.watch(repositorioFixosProvider);
  final repoGanhos = ref.watch(repositorioGanhosProvider);
  final repoGastos = ref.watch(repositorioGastosProvider);

  final fixos = await repoFixos.observar().first;
  if (fixos.isEmpty) return;

  final mesAlvo = mesAlvoDosFixos();
  final ganhosDoMes = await repoGanhos.observarMes(mesAlvo.valor).first;
  final gastosDoMes = await repoGastos.observarMes(mesAlvo.valor).first;
  final origensJaGeradas = {
    for (final g in ganhosDoMes)
      if (g.origemFixoId != null) g.origemFixoId!,
    for (final g in gastosDoMes)
      if (g.origemFixoId != null) g.origemFixoId!,

  final aGerar = fixosParaGerar(
    fixos: fixos,
    mesAlvo: mesAlvo,
    origensJaGeradasNoMes: origensJaGeradas,
  );

  for (final fixo in aGerar) {
    if (fixo.tipo == TipoFixo.ganho) {

            ref.invalidate(fixosProvider);
